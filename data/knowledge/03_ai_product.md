# AI 产品经理面试题库（AI 产品理解 + RAG + Agent）

---

# 一、AI 产品理解

## 1. 什么是 AI 产品经理？

**回答：**

AI 产品经理是负责将人工智能技术能力转化为用户价值和商业价值的人，需要同时理解业务场景、用户需求以及 AI 技术边界。

相比传统产品经理，AI 产品经理不仅关注功能设计，还需要理解大模型能力特点，包括模型选择、Prompt 设计、知识增强、Agent 工作流、模型评测以及数据闭环等。

从产品角度来看，AI 产品经理的核心工作是解决“什么问题适合用 AI 解决，以及如何让 AI 稳定地产生价值”。

例如，在企业知识问答场景中，AI 产品经理需要设计知识库构建、RAG 检索流程、回答评价机制，而不仅仅是设计一个聊天界面。

因此，AI 产品经理本质上是连接业务需求和 AI 技术能力的桥梁，需要具备产品思维、技术理解和行业认知三方面能力。

---

## 2. AI 产品和传统互联网产品有什么区别？

**回答：**

AI 产品和传统互联网产品最大的区别在于产品交互方式和能力来源不同。

传统互联网产品通常基于明确的业务规则和确定性的程序逻辑，例如搜索、推荐、电商交易流程，产品经理主要设计用户流程、功能模块和业务规则。

而 AI 产品更多依赖模型能力，通过概率生成方式完成任务，因此产品设计重点从“功能设计”转变为“能力设计”。

主要区别有三个方面：

第一，交互方式不同。

传统产品通常是用户点击按钮完成任务，而 AI 产品更多采用自然语言交互。

第二，产品逻辑不同。

传统产品依赖固定规则，而 AI 产品存在不确定性，需要通过 Prompt、知识库、工具调用、模型评测等方式提高可靠性。

第三，迭代方式不同。

传统产品主要通过需求分析和功能迭代优化，而 AI 产品需要持续进行数据收集、模型优化和效果评估。

因此，AI 产品经理不仅需要关注用户体验，还需要关注模型效果、准确率、幻觉率等 AI 特有指标。

---

## 3. AI 产品最大的挑战是什么？

**回答：**

我认为 AI 产品最大的挑战是如何解决模型能力和业务可靠性之间的矛盾。

大模型具备很强的语言理解和生成能力，但本质上仍然是概率模型，存在幻觉、知识过时、推理错误等问题。

因此，在真实业务场景中，不能简单依赖模型生成，而需要通过产品和技术方案进行约束。

例如企业智能客服场景，需要通过 RAG 将企业知识库接入模型，让模型基于可信知识回答；同时通过评测体系监控回答准确率、召回率和用户满意度。

另外，AI 产品还面临数据质量、成本控制、用户信任等挑战。

因此，AI 产品经理的重要能力不是单纯追求模型能力，而是在效果、成本、安全和用户体验之间找到平衡。

---

## 4. AI 产品设计流程是什么？

**回答：**

AI 产品设计流程相比传统产品会增加 AI 能力验证和效果评估环节。

通常包括六个步骤：

第一，需求分析。

明确用户痛点以及是否适合使用 AI 解决。

第二，场景拆解。

分析任务复杂度、数据来源、用户交互方式，例如判断是否需要 RAG 或 Agent。

第三，AI 方案设计。

包括模型选择、Prompt 设计、知识库建设、工具调用以及系统架构设计。

第四，Prototype 验证。

通过 Prompt Demo 或小规模 MVP 验证 AI 效果。

第五，效果评测。

建立评价指标，例如准确率、召回率、幻觉率、响应速度以及用户满意度。

第六，持续优化。

通过用户反馈和数据闭环不断优化模型和产品。

AI 产品最大的不同是需要先验证 AI 能力是否达到可用标准，再进行规模化产品建设。

# 二、RAG

## 5. 什么是 RAG？

**回答：**

RAG 全称 Retrieval-Augmented Generation，即检索增强生成，是一种结合信息检索和大语言模型生成能力的技术架构。

其核心思想是：在模型生成答案之前，先从外部知识库中检索相关信息，然后将检索结果作为上下文输入给大模型，让模型基于真实资料生成答案。

相比直接使用大模型，RAG 可以解决模型知识更新困难、企业私有知识无法获取以及降低幻觉等问题。

例如智能客服系统，可以将产品文档、FAQ、规则制度存入知识库，用户提问后先检索相关内容，再让模型生成回答。

---

## 6. 为什么需要 RAG？

**回答：**

需要 RAG 主要有三个原因。

第一，大模型知识存在局限。

大模型训练数据存在截止时间，无法实时获取企业内部数据。

第二，大模型容易产生幻觉。

模型可能生成看似合理但实际上错误的信息。

第三，企业需要知识可控。

企业应用通常要求回答必须基于内部规范，而不是模型自由生成。

RAG 通过外部知识增强，使模型回答更加准确、可解释，并且知识更新成本更低。

相比重新训练模型，RAG 只需要更新知识库，因此更加适合企业场景。

---

## 7. RAG 的完整流程是什么？

**回答：**

一个完整 RAG 系统一般包括离线知识处理和在线问答两个阶段。

### 离线阶段：

首先，对企业文档进行数据清洗；

然后进行文本切分，将长文档拆成适合检索的小块；

之后通过 Embedding 模型转换成向量，并存储到向量数据库。

### 在线阶段：

用户提出问题后，系统首先对 Query 进行向量化；

然后通过向量检索或者混合检索找到相关知识；

接着通过 Rerank 模型重新排序，提高相关性；

最后将检索结果和用户问题一起输入大模型，由模型生成答案。

整体流程：
文档 → Chunk → Embedding → Vector DB → Retrieval → Rerank → LLM → Answer


---

## 8. 如何优化 RAG？

**回答：**

RAG 优化通常从四个层面展开。

第一，数据层优化。

包括提升文档质量、合理切分 Chunk、增加 Metadata 信息。

第二，检索层优化。

可以采用混合检索，将关键词检索 BM25 和向量检索结合，提高召回能力。

第三，Query 优化。

例如 Query Rewrite、多 Query 扩展、HyDE 等方法，提高用户问题和知识内容的匹配度。

第四，生成优化。

通过 Prompt 约束模型必须基于检索内容回答，并增加引用来源。

此外，还可以加入 Rerank 模型，对初步召回结果重新排序，提高最终上下文质量。

---

## 9. 如何解决 RAG 检索不到？

**回答：**

RAG 检索不到通常有几个原因。

第一，Query 和知识库表达差异较大。

解决方法是 Query Rewrite，通过模型改写用户问题。

第二，Chunk 切分不合理。

如果 Chunk 太大，会降低检索精度；太小，会导致上下文缺失。

第三，Embedding 模型能力不足。

可以更换更适合业务领域的 Embedding 模型。

第四，检索策略单一。

可以采用 Hybrid Search，将关键词检索和向量检索结合。

第五，知识库本身缺失。

这种情况需要通过知识运营补充数据。

---

## 10. 如何降低 RAG 幻觉？

**回答：**

降低 RAG 幻觉需要从模型输入、生成约束和评价体系三个方面优化。

首先，提高检索质量，保证模型获得准确上下文。

其次，通过 Prompt 明确要求模型只能基于提供资料回答，如果知识不存在，需要明确说明不知道。

第三，引入引用机制，让答案展示来源，提高可信度。

第四，建立评测体系，对事实准确率、答案一致性进行持续监控。

企业场景中，RAG 的目标不是让模型回答更多，而是让模型回答更加可靠。

---

## 11. 如何评价 RAG 效果？

**回答：**

RAG 评价通常分为检索效果和生成效果两个部分。

检索层：

主要关注 Recall@K，即正确知识是否被召回。

生成层：

关注回答准确性、完整性、相关性以及幻觉率。

常见指标包括：

- Context Recall：上下文召回能力
- Context Precision：检索内容准确程度
- Faithfulness：答案是否忠于检索内容
- Answer Relevance：答案是否相关

实际企业中，还需要结合业务指标，例如用户满意度、人工转接率、客服解决率等。

# 三、Agent

## 12. 什么是 Agent？

**回答：**

Agent（智能体）是一种能够自主任务规划、调用工具并执行任务的 AI 系统。

相比传统的大模型应用，Agent 不只是进行一次性的文本生成，而是具备一定的自主决策和任务执行能力。

从技术架构来看，一个 Agent 通常由大语言模型作为核心推理引擎，通过结合任务规划（Planning）、记忆（Memory）、工具调用（Tool Use）以及执行反馈（Reflection）等模块，实现复杂任务的自动完成。

例如，一个旅游规划 Agent，不只是回答“推荐哪些景点”，而是可以理解用户需求，查询天气、搜索酒店、规划路线，并生成完整行程。

从产品角度来看，Agent 的核心价值是让 AI 从“回答问题”升级为“完成任务”。

---

## 13. Agent 和 Chatbot 区别？

**回答：**

Agent 和 Chatbot 最大区别在于自主性和任务完成能力。

传统 Chatbot 更多是基于固定流程或者单轮问答模式，用户提出问题，系统返回答案，本质上是信息交互工具。

而 Agent 更强调目标驱动，它能够理解用户目标，自主拆解任务，选择工具，并通过多轮执行完成复杂任务。

主要区别有三个方面：

第一，交互模式不同。

Chatbot 通常是用户提问，机器人进行回答；

而 Agent 是用户提出目标，Agent 根据目标自主规划执行。

第二，能力范围不同。

Chatbot 主要依赖知识库、规则或者固定流程完成问答；

Agent 可以调用外部工具，例如搜索引擎、数据库、业务 API 等，实现信息查询、数据处理以及任务执行。

第三，系统设计不同。

Chatbot 通常流程为：
用户输入 → 意图识别 → 回复生成

而 Agent 通常流程为：
用户目标 → 任务规划 → 工具调用 → 执行反馈 → 最终结果

因此，Chatbot 更像一个智能问答助手，而 Agent 更像一个能够自主完成任务的数字员工。

从产品角度来看，如果场景主要是知识查询，Chatbot 或 RAG 已经可以满足需求；如果需要多步骤推理、工具调用和任务执行，则更适合使用 Agent。

---

## 14. Agent 的核心组成是什么？

**回答：**

一个完整 Agent 通常包含五个核心组成部分。

第一，大语言模型（LLM）。

大语言模型负责理解用户意图、进行推理分析以及生成决策，是 Agent 的核心大脑。

第二，Planning（任务规划）。

负责将复杂目标拆解成多个可执行步骤。

例如用户希望制定一次旅行计划，Agent 可以将任务拆解为目的地选择、交通查询、酒店搜索、路线规划等多个子任务。

第三，Memory（记忆）。

用于保存上下文信息和用户历史偏好，使 Agent 能够进行连续交互。

Memory 通常包括短期记忆和长期记忆：

- 短期记忆：保存当前任务上下文；
- 长期记忆：保存用户历史行为和偏好。

第四，Tool Use（工具调用）。

Agent 可以连接外部工具，例如搜索引擎、数据库、业务系统 API 等，使模型具备执行真实任务的能力。

第五，Reflection（反思优化）。

Agent 根据执行结果进行检查和调整，例如发现结果不符合要求时重新规划任务。

因此，一个成熟 Agent 的核心并不是单独的大语言模型，而是：
LLM + Planning + Memory + Tools + Feedback

通过这些模块结合，使 AI 从“生成内容”进一步发展为“执行任务”。

## 15. 如何设计 Agent 工作流？

**回答：**

设计 Agent 工作流时，我认为应该从业务任务出发，而不是先考虑技术方案。

第一步，明确用户目标。

首先需要判断用户希望 AI 完成的是简单信息查询，还是复杂任务执行。

例如：

“查询订单状态”属于简单查询；

“帮我处理退款申请”则涉及多个业务步骤，更适合 Agent。

第二步，拆解任务流程。

将复杂任务拆解为多个可执行节点。

例如智能客服 Agent 可以拆解为：
用户问题理解
→ 查询订单信息
→ 判断退款规则
→ 生成解决方案
→ 回复用户

第三步，设计 Agent 决策节点。

明确哪些环节由模型自主判断，哪些环节需要调用固定工具。

例如：

- 用户意图识别可以由模型完成；
- 查询订单必须调用业务 API；
- 金额退款需要人工审核。

第四步，设计工具能力。

根据业务需求连接外部系统，例如：

- CRM 系统；
- 数据库；
- 搜索系统；
- 企业内部 API。

第五步，设计异常处理机制。

需要考虑：

- 信息不足时是否主动追问；
- 工具调用失败如何处理；
- 高风险操作是否需要人工确认。

第六步，建立评测体系。

通过任务完成率、成功率、响应时间、用户满意度等指标持续优化。

因此，Agent 设计的核心不是让模型完全自由发挥，而是在明确边界和流程约束下，提高任务自动化程度。

---

## 16. 什么情况下不应该使用 Agent？

**回答：**

并不是所有 AI 场景都适合使用 Agent。

如果任务简单、流程固定，通常不需要 Agent。

例如：

- FAQ 查询；
- 简单信息检索；
- 固定格式内容生成。

这些场景使用传统 Chatbot 或 RAG 就可以满足需求。

另外，如果任务风险较高，也不适合完全交给 Agent。

例如：

- 金融交易；
- 医疗诊断；
- 法律决策。

因为 Agent 具有自主规划和执行能力，同时也存在一定的不确定性，因此需要增加人工审核和安全控制机制。

判断一个场景是否适合使用 Agent，我通常考虑三个因素：

第一，任务是否复杂，是否需要多步骤执行。

如果只是简单问答，没有必要引入 Agent。

第二，是否需要调用外部工具。

如果任务涉及数据库查询、业务系统操作或者信息获取，Agent 的价值更明显。

第三，自动化收益是否超过系统复杂度成本。

如果 Agent 带来的效率提升有限，但增加了开发、维护和风险控制成本，那么可能不是最优方案。

因此：

- 简单知识问答 → Chatbot / RAG；
- 多步骤任务执行 → Agent；
- 高风险业务 → Agent + 人工审核。

Agent 的核心价值不是替代所有产品，而是在复杂任务场景中提升自动化能力。
